# Теплолюкс — ERP

Внутренние рабочие места сотрудников поверх **Dolibarr 24.0.0**. Компания перешла с SAP B1 на
Dolibarr, но обычный интерфейс Dolibarr оказался неудобен для повседневной работы — поэтому у каждой
роли своё узкое приложение, а Dolibarr остаётся единой базой и единственным источником правды.

Все три инструмента общаются с Dolibarr **только через REST API** (плюс прямой SQL там, где REST не
умеет нужного). Своей параллельной бухгалтерии нет: счета, склад и деньги живут в самом Dolibarr и
видны в нём обычным образом.

---

## Инструменты

| Папка в репозитории | Кто работает | Порт | Что делает |
|---|---|---|---|
| `custom/teplouxkassa` | Жамшид (Жоми), MuhammadAli (Турк) | 8010 | Продажи, касса и долги клиентов, приём товара по заказам, инвентаризация, перемещения, возвраты, авансы и выдача денег, сменный отчёт, черновики продаж |
| `custom/nodirtool` | Нодир, Абдурашид (закупщики) | 8011 | Заказы поставщикам и спецификации, логистика и партии, себестоимость, оплата поставщикам, перевозчики, зарплата, хозрасходы и доходы, почта поставщикам |
| `custom/bosstool` | Умид (шеф), Суннатилла | 8012 | Заявки на закупку, своя касса, отчёты по деньгам, продажам, закупкам и потребности в товаре |

Размер: 25 / 37 / 17 страниц соответственно.

### Изоляция направлений

Бизнес разделён на **Жоми** (коды `J*`) и **Турк** (коды `T*`), и это не косметика: Жамшид и
MuhammadAli не должны видеть данные друг друга. Платный модуль Multicompany не покупали — изоляция
достигается тем, что эти сотрудники вообще не заходят в Dolibarr, а работают только в своём
приложении с жёстко заданными границами.

Границы направления заданы **ровно в одном месте** — `custom/teplouxkassa/config/config.zhomi.php`
и `config.turk.php`. Товар относится к направлению по доп.полю **`kod_sap`**, а не по `ref`
(`ref` после миграции из SAP хранит код поставщика). Клиенты — по префиксу `code_client`.

Проверка направления стоит на сервере в каждом действии, а не только в интерфейсе: подстановка
чужого `id` в запрос отбивается.

## Как это развёрнуто

⚠️ **Папка `custom/` в репозитории — это только способ разложить код.** Это **не** модули Dolibarr,
их нельзя копировать в `C:\Dolibarr\htdocs\custom\`. Это три самостоятельных сайта IIS:

| Репозиторий | Реальный путь на сервере | Сайт IIS |
|---|---|---|
| `custom/teplouxkassa` | `C:\TeplouxKassa` | TeplouxKassa (8010) |
| `custom/nodirtool` | `C:\NodirTool` | NodirTool (8011) |
| `custom/bosstool` | `C:\BossTool` | BossTool (8012) |

Сам Dolibarr — `C:\Dolibarr\htdocs` (Default Web Site, порт 80), документы вне веб-корня в
`C:\Dolibarr\documents`.

**Стек:** Windows Server 2022, IIS + FastCGI, PHP 8.2 NTS, MariaDB 11.8, Dolibarr 24.0.0.
Фреймворков нет — обычный PHP, вся логика в самих страницах плюс общие файлы в `includes/`.

> Планируется переезд всей связки на отдельный VPS. IIS-специфичные куски (настройка сайтов,
> FastCGI, URL Rewrite) там придётся переделать на Apache/Nginx.

## Запуск на новом сервере

1. Скопировать папки из `custom/` по путям из таблицы выше.
2. Создать сайты IIS на портах 8010/8011/8012, физический путь — соответствующая папка,
   стартовая страница `index.php`. В каждой папке уже лежит нужный `web.config`.
3. **Заполнить конфиги.** В репозитории лежат только образцы с заглушками:

   ```
   custom/teplouxkassa/config/config.zhomi.example.php  → config.zhomi.php
   custom/teplouxkassa/config/config.turk.example.php   → config.turk.php
   custom/teplouxkassa/config/db.local.example.php      → db.local.php
   custom/nodirtool/config.example.php                  → config.php
   custom/nodirtool/config/db.local.example.php         → db.local.php
   custom/bosstool/config.example.php                   → config.php
   custom/bosstool/config/db.local.example.php          → db.local.php
   ```

   Везде, где стоит `ЗАМЕНИТЬ_...`, вписать настоящее значение: API-ключи служебных пользователей
   Dolibarr, пароли входа в приложения, пароль к базе.

4. **Наложить патчи ядра Dolibarr** — см. [`patches/README.md`](patches/README.md). Без них не
   работают документы к заказам поставщику и ломается частичная оплата поставщику.
5. Проверить, что REST API Dolibarr отвечает: `GET /api/index.php/status`. На IIS для этого нужен
   URL Rewrite с пробросом `PATH_INFO` и `cgi.fix_pathinfo=1`.

### Служебные пользователи Dolibarr

У каждого инструмента свой пользователь API с минимально необходимыми правами — так кассир не видит
закупочных цен, а закупщик не лезет в клиентские счета.

| Пользователь | Инструмент | Права |
|---|---|---|
| `api_zhomi`, `api_turk` | TeplouxKassa | товары, клиенты, склад, счета, банк. **Без** закупок и поставщиков |
| `api_purchasing` | NodirTool | закупки, поставщики, счета поставщику, банк |
| `api_boss` | BossTool | чтение почти всего + банк для своей кассы. **Без** права создавать и удалять документы |

Сами ключи в репозитории отсутствуют — они в конфигах на сервере.

## Как устроен код

Единый набор приёмов во всех трёх инструментах:

- **POST → Redirect → GET.** Всё, что создаёт документ или двигает деньги, после успеха делает
  редирект и показывает разовое сообщение (`flash_set()`/`flash_get()`). Обновление страницы (F5)
  не повторяет операцию. Плюс блокировка кнопки от двойного клика
  (`assets/no-double-submit.js`).
- **CSRF** — один токен на сессию, проверяется в `includes/auth.php` на каждом POST.
- **Выбор контрагента живёт в сессии**, но сбрасывается на обычном GET
  (`reset_selection_unless_preserved()`) — переход по меню и обратно возвращает к списку, а не
  «залипает» на прошлом клиенте. После редиректов форм выбор сохраняется одноразовым флагом.
- **Форме не доверяем.** Цены, товары, склады и суммы перезапрашиваются с сервера перед проведением,
  а не берутся из скрытых полей.
- **Excel без библиотек** — SpreadsheetML вручную, `includes/xls_helper.php`.
- **Своё имя сессии у каждого инструмента.** Браузер не различает сайты по порту, поэтому без этого
  вход в один выбивал бы из остальных.
- **Свои таблицы** (`llx_nt_*`, `llx_boss_*`, `llx_supplier_*`, `llx_draft_order`) — только там, где
  у Dolibarr нет подходящей сущности: партии и логистика, зарплата, заявки, журналы. Деньги при
  этом всегда идут настоящими проводками в `llx_bank`.

### Валюты

Учёт с клиентами ведётся в долларах, а карта/QR/переводы принимаются в сумах; у части поставщиков
договоры в евро и рублях. Общее правило: **курс вводится вручную в момент операции**, а не берётся
из справочника Dolibarr. Реальная сумма в валюте счёта ложится на счёт как есть, долларовый
эквивалент считается по введённому курсу и виден в комментарии проводки и в квитанции.

Направление курса везде одинаковое — **единиц валюты за 1 доллар**, под полем показывается обратная
величина, чтобы нельзя было понять наоборот.

## Что стоит знать до правок

- **mysqli в PHP 8.1+ бросает исключение**, а не возвращает `false`. Привычная проверка
  `if (!$stmt->execute())` не сработает никогда — нарушение UNIQUE даст белый экран вместо
  понятного сообщения. В NodirTool для этого есть обёртка `payroll_exec()`.
- **`require master.inc.php` внутри функции ломает Dolibarr**: его переменные (`$conf`, `$user`,
  `$langs`, `$db`) становятся локальными, а классы Dolibarr берут их через `global`. Либо подключать
  на уровне файла, либо переносить в `$GLOBALS` (см. `nodirtool/includes/mailer.php`).
- **Нельзя дёргать собственные страницы HTTP-запросом изнутри запроса** — PHP держит файл сессии
  заблокированным, получается взаимная блокировка. Нужный код вызывается напрямую
  (см. `nodirtool/includes/spec_render.php`).
- **`pmp` (себестоимость) через REST не записать** — Dolibarr молча игнорирует. Только прямым SQL.
- **`.ps1` с кириллицей ломается**: PowerShell 5.1 читает файл как ANSI, если нет UTF-8 BOM.
  Скрипты, которые запускает человек, пишем только латиницей.

## Синхронизация с сервером

Код живёт на сервере по путям из таблицы выше, а репозиторий — отдельная копия. Чтобы перенести
свежие изменения с сервера в репозиторий:

```powershell
.\sync-from-server.ps1
git status        # посмотреть, что изменилось
git add -A && git commit -m "..." && git push
```

Скрипт копирует три рабочие папки в `custom/` и не трогает конфиги с паролями — они исключены
`.gitignore` и в репозиторий не попадают.
