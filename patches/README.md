# Патчи ядра Dolibarr

Здесь лежат четыре файла ядра Dolibarr, в которых пришлось исправить **настоящие ошибки самого
Dolibarr** — без них наши инструменты либо не работают вовсе, либо тихо считают деньги неправильно.

> ⚠️ **Эти правки не переживут обновление Dolibarr.** После любого апдейта или переустановки их
> нужно применить заново — иначе вернутся ошибки, описанные ниже. Сначала проверьте, не исправили
> ли их официально в новой версии.

Версия, к которой всё привязано: **Dolibarr 24.0.0**.

## Что в папке

| Файл | Что это |
|---|---|
| `*.diff` | Только наши изменения, в формате unified diff относительно оригинала 24.0.0. Читать — сюда. |
| `htdocs/**` | Целиком пропатченные файлы, как они лежат на сервере. Для быстрой замены. |

## Как применить

Из корня установки Dolibarr (у нас `C:\Dolibarr`):

```bash
# вариант 1 — наложить только изменения (предпочтительно: увидите конфликты, если версия другая)
patch -p0 htdocs/api/class/api_documents.class.php        < patches/api_documents.class.diff
patch -p0 htdocs/core/lib/files.lib.php                   < patches/files.lib.diff
patch -p0 htdocs/core/lib/functions.lib.php               < patches/functions.lib.diff
patch -p0 htdocs/fourn/class/api_supplier_invoices.class.php < patches/api_supplier_invoices.class.diff
```

```powershell
# вариант 2 — заменить файлы целиком (только если версия Dolibarr ровно 24.0.0)
Copy-Item -Recurse -Force patches\htdocs\* C:\Dolibarr\htdocs\
```

В каждом изменённом месте прямо в коде стоит комментарий с пометкой `[Теплолюкс/NodirTool]` и датой —
искать по ним.

## 1. `fourn/class/api_supplier_invoices.class.php` — частичная оплата поставщику закрывала счёт целиком

**Самая опасная из четырёх: ошибка с денежными последствиями.**

Метод `addPayment()` при включённой мультивалютности (у нас включена — UZS/EUR/RUB) безусловно
записывал в `multicurrency_amounts` **полную сумму счёта**, даже когда оплачивали частично. Дальше
`PaiementFourn::getWay()` видит непустой `multicurrency_amounts`, переключается на режим `'customer'`,
а `PaiementFourn::create()` в этом режиме берёт суммы именно оттуда — и реальная частичная сумма
молча отбрасывалась.

**Как это выглядело:** заплатили поставщику 60 из 200 — счёт помечался полностью оплаченным.

**Исправление:** мультивалютная сумма считается пропорционально реально запрошенной сумме платежа.

Проверено тремя сценариями: частичная оплата оставляет счёт открытым с верным остатком; довнесение
остатка закрывает его; оплата без указания суммы («погасить остаток») работает как раньше.

---

## 2. `core/lib/files.lib.php` — нельзя было приложить ни одного документа к заказу поставщику

`api_documents.class.php::post()` приводит и `commande_fournisseur`, и `supplier_order` к строке
`supplier_order`, а проверка прав в `dol_check_secure_access_document()` знает только
`commande_fournisseur`/`order_supplier` — про `supplier_order` ей ничего не известно. Нестыковка имён
внутри самого Dolibarr.

**Как это выглядело:** любая загрузка файла к заказу поставщику отбивалась
`403 Access not allowed to upload file into this directory` — с любыми правами, у любого пользователя.

**Исправление:** добавлен алиас в уже существующий блок «Fix modulepart for backward compatibility»
(там же, где Dolibarr сам приводит `facture`→`invoice`, `propale`→`propal`).

---

## 3. `core/lib/functions.lib.php` — список документов заказа всегда приходил пустым

`getMultidirOutput()` в `case 'order_supplier'` превращал имя в `supplier_order`, но отдельного
`case 'supplier_order'` ниже по функции нет — путь так и оставался папкой с буквальным именем
`supplier_order` вместо настоящей `fournisseur/commande`, куда реально пишется загрузка.

**Как это выглядело:** файлы физически лежали на диске, а `GET /documents` отвечал «ничего не найдено».

**Исправление:** ведём сразу туда же, куда `case 'commande_fournisseur'`.

---

## 4. `api/class/api_documents.class.php` — фильтр по типу файла отсекал вообще всё

`explode(",", "")` возвращает `[""]` — массив с одним пустым элементом, а **не** пустой массив.
Поэтому `!empty($arraycontenttype)` было истиной даже когда фильтр не запрашивали вовсе, и список
отфильтровывался до пустого (ни у одного реального файла content-type не бывает пустой строкой).

**Исправление:** добавлена явная проверка, что `$content_type` действительно передан — ровно то, что
написано в комментарии Dolibarr строкой выше («if provided»).

> Причины 2, 3 и 4 независимы: они ломали один и тот же сценарий «документы к заказу поставщику» в
> трёх разных местах. Без любой из трёх раздел не работает.
